2. Copy buttons.
3. The Frame stiffness window has its own level selector, independent of the drawing pad.
4. Module 3 gets a load-area box on each level row (option a: a level with its box off, or with invalid areas, uses its psf).
5. Each level has its own ID list.

The archive copy `_archive/SEISMIC ELF - Rigid - BraceFrame - Dashboard-LR (before 2026.10.16 multi-level).html` is the file before this change.

- **Data:**
  - `l.As[j]` = brace area of frame l in story j+1; `braceA(l, i)` falls back to `l.A`.
  - `S.plan.lv[j]` = `{la, laIds, laActive}` for level j+1.
  - `S.levels[j].la` = that level's module 3 box; `S.plan.padLv` = the drawing pad level.
  - `ensureLevels()` (called by normalize, `resize` and at start-up) sizes these to n. New levels copy the level below.
  - Older projects (one `plan.la` / `laIds`, one `S.useLA`) open with that set at every level, and each level's box set from `useLA` (checked).
- **Module 2:**
  - A "Level" dropdown (accent red) at the right of the toolbar, with "Copy to all levels" (click twice) and "Copy from …"; both copy brace areas and load areas, and Undo reverses them.
  - The Braced frames and Loading areas panels carry a "Level: …" tag and show the pad level. The A boxes, the frame table's A column ("this level") and the load areas all edit that level.
  - The pad's C.M. and C.R. markers and the CR / eccentricity stats follow the pad level.
  - The two panels split the side column 50/50, and each list scrolls.
  - Frame stiffness keeps its own selector (`kStory`), relabelled "Level (its braces are the story below it; independent of the drawing pad level)".
- **Calculation:**
  - `laStats(lv)`, `laOn(lv)` (box on and areas valid), `cmPt(st, lv)`, `hdGeometry(dir, lv)` (carries `G.lv`).

  - Modules 9, 10 and 11 build the beam for the level they show. Module 9's "Reactions at every level" solves each level's own beam.
  - `frameGeo(l, i)` uses `braceA(l, i)`.
  - Module 12 adds up the levels (`frameStoryShears`):

    - Flexible: each level's own beam reaction, split among the frames on the line by story i stiffness.

  - Module 12's story table shows A per story; the frame summaries show the range ("10 to 30").

- **Module 2:**
  - **Drawing:** a "Load areas" tool after Select/move. Click one corner, then the opposite corner. Corners snap to outline corners, load-area corners, outline and load-area edges, alignments and the grid (`snapLA`). A rubber-band rectangle shows W × D while drawing.
  - **Refused areas:** a new area takes the highlighted ID and is refused (message) if it overlaps an area or is outside the plan.
  - **Display:** a "Show loading areas" checkbox (plan option `la`) sits under the hint on the pad. Areas are drawn translucent by ID color, clipped to the outline, with an ID box at each area's centroid. Uncovered parts of the plan are hatched (`laGaps`), and an overlap is drawn in red.
  - **Select/move:** clicking inside an area selects it (after frames and edges). Drag moves it; a move that would overlap is undone with a message. Delete removes it, and Undo works.
  - **Loading areas panel:** under Braced frames, in a shared side column `.pside`; both panels shrink and scroll. Rows show color, ID, psf and area (ft²), plus × (click-twice when the ID has areas, which deletes them too).
    - "+ ID" adds an ID with the next number.
    - Clicking a row makes it the ID for new areas, or gives a selected area that ID.
    - Renaming an ID renames its areas (duplicates and blanks are refused).
    - The footer shows coverage: "Covers the whole plan ✓, W = … k per level, average psf", or the error.
- **Module 3:** a "Seismic weight from load areas (section 2)" checkbox (`S.useLA`).
  - When on and the areas are valid (`laOn()`), every level's w = Σ psf·A (the same at every level), and the psf column becomes plain read-only cells showing the average psf. The typed psf values are kept for when it is off.
  - When on but invalid (a gap, an overlap or a missing psf), module 3 says why and uses the psf column. The CSV export writes the average psf.
- **Calculation (`laStats`, cached on the plan JSON):**
  - Each area's area and centroid inside the plan come from slabs in x, each cut against the outline (`rectInPlan`, `cutAt`).
  - W = Σ psf·A / 1000; CM = weight centroid (`cmPt`), used by `rigidSolve`, the plan C.M. marker, the eccentricity stat and the 3D force arrows.
  - **Beam load (`hdGeometry`):** extra breakpoints at the load-area edges, and each step gets m = Σ psf × (length of the cut inside each area) in k/ft. `solveBeam` uses q = F·m/W when `G.W` is set (otherwise the old F·d/A).
  - This is exact for rectangles; the 100 × 60 hand example gives w = 1.667 / 0.556 k/ft. The diaphragm unit shear v = V/d, collectors and chords still use the geometric depth.
  - The accidental-torsion couple follows the load (spread with the mass).
- **Switch off:** everything is exactly as before (checked).

  - per-level psf;
  - typed dimensions for load areas (as for frames);
  - port to the other files if wanted.

## Editable brace-frame dimensions (LR file only, 10/15)

The user asked for this instead of snapping. Agreed plan: select a frame, then click its dimensions.

- **Use:**
  - In Select/move mode (or with a frame picked in the table), the selected frame's dimensions turn blue with a light box: the gap on each side along its line (to the outline or to the next frame on that line), and its offset from the outline when it is inside the plan (e.g. X2's 30' to the top edge).
  - Clicking one opens a number box in place (`#dimEd`). Enter applies the value exactly (no grid snap); Esc or clicking elsewhere cancels. Undo reverses it.
  - With no frame selected, the dimensions stay plain labels.
- **What moves:**
  - A gap: only the selected frame slides along its line; the gap on its other side absorbs the change.
  - An offset: the frame moves sideways to the new distance from that edge.
  - A 2X frame moves as a whole and keeps L₁.
  - Frame and bay lengths are not editable here (the frame table still does that).
- **Limits:**
  - A gap is refused if the frame would pass the outline or the nearest frame on its line; the message gives the largest value allowed.
  - An offset is refused if the frame would leave the outline (five points along the frame are tested with `pip`).
  - A neighbor touching the frame leaves no editable gap on that side.
  - Messages show in `#planMsg` for 4.5 s.
- **Code:**
  - `dimS(..., ed)` draws the highlight box and records a hit box in `dimEdits` (reset in each `render()`).
  - `lfrsDims()` builds the `ed` objects for the selected frame (`bnd` = limits from the outline and the neighbors on the line).
  - `openDimEd()` / `applyDimEdit()` / `closeDimEd()` handle the box; the plan's pointerdown checks `dimAt()` before frame hit-testing.
  - The box's keydown stops propagation, so Backspace edits the number and does not delete the frame.
- **Not yet in** the Dashboard or original BraceFrame files.

## Scope and assumptions (user, 10/13)

- **Frames:** one diagonal brace per frame per story, or a two-bay X (2X, added 10/14, see below). No single-bay chevron yet.
- **Connections:** everything pinned. No gussets and no rigid offsets; L_br is the calculated work-point length.
- **Deformations:** columns and beams are axially rigid. Column axial deformation is to be added later.
- **Steel:** E is the same for every brace (29,000 ksi).
- **Brace size:** one brace area A per frame, used for every brace at every story (2X included).
- **Story heights:** each story uses its own height from section 3.
- **AISC 341:** not checked yet (for example the 30/70 tension rule on a line).

## Two-bay X frame (2X), added 10/14

User's answers (10/14):
1. Λ by default, with a V option.
2. One A for every brace.
3. An odd number of stories is fine.
4. Elastic distribution only; AISC 341 is not checked.

- **Geometry:**
  - Three columns: start, middle at L₁ from the start, and end. L₁ defaults to L/2 and is also used when the entry is invalid.
  - Story 1 is Λ (both braces meet at the middle column at the top) or V (both leave the middle column at the bottom).
  - The pattern flips every story, so each pair of stories forms an X over two stories.
  - With an odd number of stories the top story is a half X; the app notes this in module 12.
- **Data per frame:**
  - `type` is 'single' or 'x2'.
  - `L1` is the middle column offset from the start (ft).
  - `mid` is 'top' (Λ in story 1) or 'bot' (V in story 1).
  - `up` and `alt` are not used for 2X.
- **Helpers:**
  - `frameCols(l)` gives the column offsets [0, L] or [0, L1, L].
  - `storyBraces(l, i)` gives the braces in story i as {bay, from, to} column indices (bottom → top).
  - `frameConns(l, i)` gives the brace tops at level i grouped by column (offset, stiffness fraction).
- **Stiffness:**
  - The two braces of a story act as parallel springs: k = k₁ + k₂, each k = A·E·cos²θ/L_br for its own bay and the story height.
  - Equal bays are about 1.47× a single 22 ft diagonal in the sample (shorter, steeper braces). Unequal bays put more stiffness in the shorter bay.
- **Distribution:**
  - The story shear splits between the two braces by k-share; this is exact for rigid columns and beams (checked against a three-column truss).
  - The middle column carries zero only when the bays are equal.
- **Module 10:**
  - The frame reaction goes in as a point load at each column where a story-below brace tops out, split by brace stiffness.
  - Λ below: the whole R goes to the middle column. V below: R is split to the two end columns.
  - A 2X never needs a frame-beam through-force, because the braces above and below meet at the same columns.
- **Module 12:**
  - Column axial by joint equilibrium from the roof down, for any number of columns: N_below = N_above − Σ P·sinθ (story braces topping out at the column) + Σ P·sinθ (braces of the story above starting at the column).
  - Checks: ΣFx = ΣFy = ΣM = 0 at every story cut, with moments taken about the start column.
  - The elevation, OT and three column bars are drawn. The summary table shows "L₁ + L₂" and three base column forces.
- **UI:**
  - Side panel row: A, a Λ/V button, and a "2X" toggle.
  - Frame table: "Type" (Single / 2X plus an L₁ box) and "Story-1 brace" (Λ at top / V at bottom).
  - Stiffness table: the two bays on two lines, with k shown as total over "k₁ + k₂".
  - Plan: three column squares, triangles pointing to the middle column (Λ) or the ends (V), and the label "X5 · 2X". The dimension chain shows both bays.
  - 3D: two braces per story.

## Distribution

- **Sections 9 to 11:** the level-x force (Fx or Fpx) is distributed with the frame stiffness of story x, the story directly below level x.
- **Rigid model:** the same CR/J procedure as before, per story.
- **Flexible models:** frames on one line now share the line reaction by stiffness (it was by length).
- **Section 12:** story-shear method. V_i = Σ Fx at and above level i, distributed with the stiffness of story i. Frame force at a level = V_i − V_{i+1}.
- **Open point:** when story heights differ, section 12's level forces include transfer effects that section 9 doesn't show.
  - Example: sample plan with a 15 ft first story, Y1 at Lvl 1. Section 12 gives 41.7 k; section 9 shows the story-1 share × F1.
  - Option for later: drive section 9's Fx case with V_j,x − V_j,x+1.

## Module 10

- **Own pulldowns (10/14):** diaphragm model and accidental torsion (Envelope of ±5% default, +5%, −5%, None), independent of module 9. The through-force table uses module 10's model and torsion case.

- **Location cursor (10/14):** as in modules 9 and 11.
  - Controls: a slider, a number box, "Go to max collector force", and drag on the diagram (it snaps to break points).
  - Cards: the point, vᵤ, C and Ω₀·C. At a brace connection they show C before / after, both ±5% cases in the envelope.
  - Diagram: a dashed line, a dot per case, and a value label. It replaces the break-point label at that spot, and the other labels avoid it.
- **Labels (10/14):** each value and its Ω₀C are placed as one block. A block that would collide moves away from the curve, then to the inside of the curve; if no spot is free, the label is left off (the break-point table still has it). Connection labels are placed first.
- **Point reactions:** each frame takes R as a point load at the top end of the brace from the story below. C drops by R there, and break points show both sides ("before" / "after").
- **Ω₀:** applied at every break point, including both sides of each connection.
- **Through-force table:**
  - For stacked braces, the frame beam carries the story shear of the story above (Fx, using module 10's own model and torsion case) between the two columns.
  - Shown separately, not added to the collector force.
  - If both braces meet at the same column (alternating), there is no through-force.

## Module 12: Braced Frame Forces

- **Per story:**
  - level force;
  - story shear V;
  - brace force P = V / cos θ (T when the brace rises toward the end the load pushes toward);
  - OT at the floor below;
  - column axial by statics. For a single frame this is the M/L_b result: the column at the brace's top end carries M at the floor below / L_b, and the other column carries M at the floor above / L_b. The start-end column is in tension for +X / +Y. Since 10/14 the forces are computed by joint equilibrium (below), which gives the same values.
- **Checks:** ΣV·h = M, and ΣFx = ΣFy = ΣM = 0 at every story cut.
- **Column axial (10/14):** by joint equilibrium from the roof down (same results as the M/L_b formula for single frames; also works for 2X).
- **Envelope:** ±5% envelope by base OT, as before.
- **Removed:** the unit-shear and "decoupled T/C" wording.
